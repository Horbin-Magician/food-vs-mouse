# 战斗操作与食谱菜单整理

状态：2026-09-26 已实现；自动、原生画面与关键鼠标验收见 [专项记录](../testing/ui_refresh.md)。适用「使用体验」里程碑的战斗 HUD、顶部卡牌与关前小铺。沿用 [UI 规范](ui.md)、[棋盘布局](perspective.md)、[商店流程](../design/shop.md)、[设置](../design/settings.md) 及 [经济规则](../design/economy.md)，不调整玩法、数值、存档或模块接口。

## 信息层级

- 保留墨绿、奶油白、黄铜与暖光的深夜食堂主题；顶部只保留热量、卡牌、粮仓、本局灵感、设置和图标锅铲。删除棋盘两侧重复的粮仓与关数悬挂牌，棋盘坐标、尺寸与鼠标命中保持原样。
- 顶部卡牌仍为 72×76、图上费下、强化星角标；冷却阴影上增加居中整数剩余秒数，向上取整，最后不足一秒仍显示 1。它只读取原冷却，暂停冻结，准备阶段隐藏；不增加卡牌底部状态行。费用不足继续灰显，详情悬停保留。
- 既有底栏左侧保留食堂标识，中部显示当前操作情境：选中美食的名称、费用与可放置状态，锅铲的立即移除／无返还，或未选中时的「选美食，守住粮仓」。这是跟随操作的状态，不恢复顶部提示栏或教学流程。
- 底栏提供可辨认的已购食谱数量与悬停说明；右侧关数、难度、真实鼠潮生成进度与场上余鼠保持一处显示。进度满仍标记清理余鼠，不等同胜利。

## 关前食谱菜单

- 保持居中 840×556 模态与现有节点接口，以「打烊小铺 / 本关开战前」作为标题层级。显示第几关、锁定难度与现有热量；注明购物与布阵共用余额、准备阶段不恢复。价格从配置读取。
- 最多三张食谱使用菜单卡：用途（适用美食或全阵容）、名称、现有效果描述、价格，以及买后可用于布阵的剩余热量。不足时直接显示还差多少热量，而非只变灰；卡片点击仍直接调用购买业务，购买不增加确认。
- 新局 150 热量而食谱更贵的情况必须明确显示「先开战积攒热量」，不提高初始资源、不强迫刷新或购物。余额不足不影响唯一「购物完成 · 开战」按钮。
- 下方显示当前开战预算与已购食谱悬停清单；刷新按钮直接显示剩余次数、消费和不可用原因。空商品列表说明本次已无商品；当候选池已空时说明当前阵容暂无已解锁、未购买的食谱。空池不影响开战；刷新仍保留原业务规则。
- 唯一完成按钮立即保存并开战。Esc、右键、遮罩与重复点击的现有语义不变；设置仍可覆盖小铺，关闭后回到原购物状态。存档失败仍在小铺显示，不能表现为已开战。

## 边界与验收

检查 0／150／精确价格／高余额、零／三件商品、刷新耗尽、已购十二食谱、旧档八卡、完整／半程／最后一秒冷却、暂停及 2×。文字不得跨越卡片边界；已购清单可悬停读取；顶部和底部不能遮挡棋盘。检查食谱购买后余额、重复购买／开战、设置模态、拖放与右键取消。

执行 Godot 4.6.3 导入与相关逻辑／UI 回归；原生窗口在 1280×720 和 1600×900 检查小铺、战斗、选中、冷却与暂停并执行鼠标交互。自动检查不能代替视觉或真人整局平衡验证。实际结果由本次统一验收记录维护。

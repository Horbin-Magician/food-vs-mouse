# 《深夜食堂：鼠潮来袭》原型设计与实施计划

## 1. 游戏定位与完整一局

制作一款 **Godot 4.6、电脑端、鼠标操作的 2D 分路塔防肉鸽游戏**。玩家经营打烊后的食堂，让美食守住左侧粮仓，抵御从右侧涌来的鼠群。

核心乐趣调整为：**局外购卡强化与选卡 → 战斗中布阵救场 → 关间用食谱构筑 → 击杀拾取与通关赚灵感，继续培养卡片。**

2026-09-25 成长体系已接入；规则见 [灵感购卡与耗材强化](design/meta_progression.md)。原局内买卡升星已移除，新局使用局外强化；旧星级仅用于旧存档续局。自动和视觉验证边界见专项记录，新版经济与整局难度仍需真人试玩。

美术采用现代 Q 版 F 风格：包子以顶部旋口喷蒸汽，吐司以厚实外壳承担防御；美食保留食物形体，老鼠以四足姿态背负或口衔厨房物件，减少人形服饰。角色视觉依据 [F 全角色规范](art/f_restyle.md)，不改变职业与玩法。所有角色、画面、音乐和文本原创。

### 一局流程

启动先进入主菜单，可继续准备快照或新开一局；胜败后显示全屏战报，可再开局或返回主菜单。交互与边界见 [主菜单与结束界面](design/screens.md)。

1. 从局外选择场景、1～5 种美食及整局难度后出战；初始拥有包子、吐司、布丁三张 +0 基础卡。粮仓耐久 10，热量 150。
2. 进入后直接开始 1-1，难度沿用出战前选择且整局锁定（规则见 [难度设计](design/difficulty.md)）。
3. 开战后用“热量”放置美食，阻挡鼠群。
4. 战斗中点击鼠群概率掉落的灵感；过关收取剩余掉落并获得通关灵感，大关内自动开始下一小关；前四大关通关后进入食谱小铺，「购物完成」开始下一大关。具体边界见 [商店设计](design/shop.md#大关通关后开店2026-09-26)。
5. 美食位置、存活状态和剩余生命保留，进入下一关。
6. 粮仓耐久归零即失败；第五大关第 8 小关通关即整局胜利；大关末关还必须击败该关 BOSS，统一采用 [末波后倒计时结束条件](design/waves.md#小关结束条件2026-09-26)。

战斗支持暂停和 1×/2×速度；暂停时允许查看信息，不允许放置或执行战斗操作。倍速位于热量下方；Esc／右上设置进入统一暂停、声音与离开窗口，规则见 [设置设计](design/settings.md)。

## 2. 战斗、经济与成长规则

### 阵地与基础规则

- 逻辑格子 96×96 像素；老鼠按像素移动，攻击接触到的同路最近美食。
- 美食默认只能攻击本行右侧目标；特殊攻击在单位说明中明确。
- 普通弹体命中首个目标后消失；范围伤害和穿透除外。
- 美食死亡后格子空出，可重新放置；死亡不损失持有卡牌或永久强化等级。
- 老鼠越过左侧边界后扣除粮仓耐久并移除；普通鼠扣 1，精英扣 2，首领扣 10。
- 粮仓没有一次性清屏保险，漏怪必须真实影响后续决策。

### 资源

| 资源 | 获取 | 用途 | 跨关规则 |
|---|---|---|---|
| 热量 | 新局 150、自然恢复、布丁生产 | 放置美食、购买食谱和刷新 | 跨关保留，上限 9999 |
| 灵感 | 击杀概率掉落后收集、每关通关奖励 | 局外购卡、刷新 | 跨局保留，规则见 [经济设计](design/economy.md) |

热量自然恢复为每秒 2 点；准备阶段不恢复、不生产。布丁产量需点击火苗收取，完整规则见 [热量生产与拾取](design/heat.md)。

每张美食卡可无限次放置，但需同时满足费用、空格和该卡的共享放置冷却。每关开始重置放置冷却。

### 持续阵地与恢复

- 每关结束，存活美食恢复自身最大生命的 15%，不复活死亡单位。
- 正式流程购物完成后直接战斗，不再提供独立关间调位阶段。
- 锅铲点击美食立即铲除，无确认、无返还；点击空地静默，成功铲除播放动画，见 [UI 规范](art/ui.md#直接铲除与动画2026-09-25)。
- 不提供付费维修功能；存活美食只保留关间免费恢复与食谱增益。
- 不设置逐个维修，不允许通过移动或读档恢复损失的生命。
- 粮仓首版无法维修，使漏怪成为整局压力。
- 关间保留余鼠、弹体、技能状态和攻击计时，规则见 [波次设计](design/waves.md#小关结束条件2026-09-26)。

### 局内食谱商店与局外卡片

食谱商店在大关通关后开放，出现时机及终局例外以 [商店设计](design/shop.md#大关通关后开店2026-09-26) 为准；不再出售美食卡或通过重复购买升星。每次展示最多 3 张适用于携带阵容、已解锁且尚未购买的食谱，候选不足按实际数量展示。

- 食谱单价与刷新热量费用统一见 [经济设计](design/economy.md)；每店最多刷新 2 次，离店未买食谱作废。
- 不再有局内金币或通关金币奖励；热量跨关保留，开战不重置，购物消费直接影响布阵预算。
- 局外卡片的携带限制、强化属性、材料消耗、成功率及降级、卡店和灵感经济，统一见 [成长方案](design/meta_progression.md) 与 [实施规格](technical/card_progression.md)。
- 旧局内一至三星倍率只在旧快照兼容模式保留，不出现在新局成长流程。

### 食谱规则

食谱统一在局内商店花热量购买，不设置关后免费三选一。新版“灵感”专指跨局购卡货币，不再作为食谱别名；奖励规则见 [成长方案](design/meta_progression.md)。商店规则与边界见 [食谱购买](design/shop.md)。

- 每次小铺展示最多 3 张食谱，费用见 [经济设计](design/economy.md)，可购买多张。
- 所有上架食谱都须能作用于本局携带单位；候选不足时按实际数量展示。
- 单位对应食谱要求本局携带该单位。
- 食谱立即作用于现有单位和后续放置单位。
- 所有伤害倍率乘算；攻速奖励先相加，再通过 `基础间隔 ÷ (1 + 攻速奖励)` 计算攻击间隔。
- 最小攻击间隔 0.25 秒；减速不叠加，取最强值并刷新持续时间。

## 4. Godot 实现方案与交互

沿用现有 Godot 4.6 工程，使用 **GDScript、2D 场景和 Compatibility 渲染器**。逻辑分辨率 1280×720，保持宽高比缩放。

### 模块与数据接口

| 模块 | 职责 |
|---|---|
| RunController | 管理开局、准备、战斗、结算、胜败状态及切换 |
| BoardController | 管理格子占用、放置、移动、移除和行内目标查询 |
| CombatController | 管理攻击、弹体、伤害、状态效果、死亡和漏怪 |
| WaveDirector | 按生成时间表与随机种子投放敌人 |
| ShopController | 局内食谱商品生成、支付和刷新 |
| MetaProgression | 局外卡片实例、卡店、强化、锁卡与携带规则 |
| RecipeSystem | 根据食谱 ID 提供属性修正与事件效果 |
| SaveService | 保存局外解锁和关间存档 |

使用 Godot 自定义 `Resource` 配置 `FoodDef`、`EnemyDef`、`RecipeDef`、`WaveDef`，均以稳定字符串 ID 引用。运行状态与资源定义分离，不修改共享资源。

`RunState` 保存：种子及随机状态、关卡、整局难度、热量、逐关灵感收集流水、粮仓耐久、携带卡实例与等级快照、已选食谱、阵地单位类型／格子／当前生命、当前阶段和商店／奖励状态。

战斗通过 `unit_died`、`enemy_leaked`、`wave_cleared` 等信号传递事件；伤害统一经过同一结算入口。计时使用游戏时间，使暂停与倍速一致影响战斗、生产和状态持续时间。

### 存档与开发辅助

- 阵地快照只在准备阶段保存；保存购买及刷新后的状态。灵感拾取即时保存局外资产及逐关最高累计，不保存战斗现场。

### 必须验证的功能

- 费用不足、卡牌冷却、重复点击不会错误扣费或重复放置。
- 满盘、空路、同时死亡、最后一只敌人与粮仓同时受击均能正确结算；粮仓归零优先判负。
- 永久强化和食谱同时作用时数值正确，不重复注册效果。
- 关间恢复、移除、读档不会意外满血或复制单位；旧维修字段不再触发治疗或扣费。
- 暂停与倍速正确作用于攻击、生产、减速和生成时间。
- 商店无法负余额购买；局外每件商品限购且材料不重复消耗；食谱不重复、不出现无法选满候选的卡死。
- 相同种子与相同操作序列可复现生成、商品和食谱结果。
- 关间存档恢复后，阵地、资源、奖励和商店保持一致，不能重复领取奖励。
- 目标设备上 40 个美食、100 个敌人及其攻击效果同时运行时，目标保持 60 FPS。

### 玩法验收与迭代顺序

邀请至少 5 名新玩家试玩，记录至少 15 局；这些数据用于发现问题，不作为最终平衡结论。

- 新玩家能在第一关理解资源、放置和阻挡。
- 至少两种构筑可以通关，且其关键选择不同。
- 中后期仍需要补位、调整阵型或购买决策。
- 旧八关单局 20～25 分钟目标已废弃；连续四十关实际时长记录于专项验收。
- 不存在靠持续堆布丁稳定溢出资源、全输出无代价通关等明显单一最优解。

若阵地滚雪球过强，依次调整敌人数量与组成、关间恢复、经济产量；若前期频繁崩盘，优先调整第一至三关生成节奏和初始热量。完成上述闭环后，再考虑新增场景、分支路线或更多角色。

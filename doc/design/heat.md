# 热量生产与拾取

状态：已实现；导入、12 组回归及实际窗口拾取验证通过，缩放限制见验证记录。适用：战斗骨架、使用体验与经济平衡迭代；依据用户 2026-09-13 的降低自然增长、点击火苗收取需求，更新 [首版基线](../TODO.md)。

## 规则与数据

- 自然恢复由 5 改为 2 热量／游戏秒（降低 60%），每关初始值和上限仍依据基线。此值为本次可逆调参选择，完整七路平衡待试玩。
- 所有 `kind=producer` 的场上美食等待完整生产周期后，冒出一团橙金火苗。每周期产量仍按 `production × star_production + 焦糖加倍` 计算，生成时快照，星级／食谱不会追溯修改已有火苗。
- 火苗待在来源格内上方，标出可收取数量；不设超时消失。同一来源尚未点击的火苗合并后续产量，保持原位置，避免叠图和重复点击负担。来源被铲除或死亡后，已产火苗仍可领取。
- 左键点击火苗立即锁定该笔数量，沿弧线飞向左上角热量数值中心；经过 `heat_flight_duration=0.45` 游戏秒到达时，由业务层调用统一热量结算。飞行中不再可拾取，重复点击无收益；此时同一来源新产量生成独立待拾取火苗。
- 暂停禁止拾取，生产、冒出／悬浮、飞行与入账全部冻结；2×同步加速。准备、选谱和胜败不能领取；关末清除待收和飞行火苗，不延迟结算、不计入下一关。重开与读档创建新战斗控制器，火苗不保存，战斗退出仍恢复准备快照。
- 到达时按实时热量应用上限，超出部分计入既有 overflow；生成时热量已满仍能产出。自然恢复与击杀食谱「余温回收」维持直接入账。

## 模块与表现

CombatController 持有独立临时火苗数组（局内 uid、来源 uid、格坐标、amount、age、flight），负责生产、合并、飞行计时、一次性入账与清理。RunController.collect_heat(uid) 校验战斗阶段及暂停，调用 CombatController 的领取请求；UI 不修改余额或驱动入账，不额外消费随机源。所有动画直接读取固定模拟步推进的 age/flight。

主场景复用原创 `assets/ui/flame.svg`，无新外部素材或依赖；冒出时间 0.35 游戏秒，火苗约 32×38 像素、点击区 52×58 像素，暖金光晕及 +数量提示。覆盖在单位之上，顶部下方的单位火苗仍留在棋盘内。飞行效果在 UI 上方、弹窗遮罩下方绘制；到达热量数值中心消失。点击火苗优先于选卡后的放置及锅铲，保留工具选择；暂停点击仅提示且不穿透棋盘。拖卡松手仍按既有放置规则处理，不误收火苗；模态弹窗阻断拾取。

## 验收

1. 自然恢复 2／秒，准备和暂停不增长；生产首周期、星级和食谱数量正确，生成不直接入账。
2. 点击后先飞行再入账，重复点击无重复收益；暂停冻结和 2×计时一致；到达时封顶及 overflow 正确。
3. 多来源、连续周期合并、飞行中再生产、来源消失、关末／胜败／重开／恢复清理。
4. Godot 导入与既有回归；真实窗口检查冒出、数量、点击不穿透、飞行终点、暂停、选卡／锅铲及等比缩放。

实际记录见 [热量验证](../testing/heat.md)；本项不代表完整平衡验收通过。

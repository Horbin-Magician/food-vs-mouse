# 主菜单与结束界面

卡片体系更新（2026-09-25）：已加入主菜单“美食卡册”、卡店／强化／出战三页，新局和再战先选 1～5 种卡；已有对局需确认结束才可修改局外资产。战报增加本局灵感。原菜单、胜败冻结、结算失败重试逻辑沿用。规则见 [成长方案](meta_progression.md)，验证见 [专项记录](../testing/meta_progression.md)。

状态：已实现，真实鼠标验收待完成，属于「使用体验」里程碑；验证见 [验收记录](../testing/screens.md)。玩法与存档基线见 [TODO](../TODO.md) 和 [运行模型](../technical/runtime.md)。

- 所有主要页面提供统一设置入口，Esc 打开，暂停、声音及返回菜单／退出规则见 [设置设计](settings.md)。
- 启动进入主菜单，不自动开局或写档。显示游戏标题、原创厨房与角色、继续游戏、新的一局、退出游戏。
- 主菜单只读校验准备快照；有效时显示可继续关卡。缺失时禁用继续；损坏／未知版本时显示具体错误，可新开局，独立局外进度不主动清空。
- 新局在出战阵容页统一选择三级难度，出发后整局锁定，小铺只显示当前难度，规则见 [难度设计](difficulty.md)。
- 新局／继续进入后立即打开本关小铺，购物完成直接开战，无额外底栏开战步骤，见 [商店流程](shop.md#购物完成即开战2026-09-25)。
- 继续通过 RunController.resume_run 恢复准备快照，明确战斗中退出会回到本关开战前。新的一局存在有效快照时先确认结束旧局，按原有规则结算解锁；取消不修改文件。恢复或结算失败留在菜单显示错误。
- 胜败由现有 RunController 判断，粮仓归零优先判负。结束界面只读取结果，不重复结算，不修改随机状态。显示胜／败标题、已通过关数、模拟战斗时长、击杀、漏怪造成的粮仓损失、美食阵亡及已购食谱数量；不虚构奖励或评分。失败说明当前失守关卡。
- 结束界面提供再守一夜、返回主菜单、退出；再开新局重置暂停、速度、选择与动画。未完成的持久化结算需重试成功后才能离开战报，错误可见，避免失败写档被新局覆盖。
- 新增入口场景负责菜单、游戏实例、结果页生命周期；战斗场景仍负责棋盘与商店，RunController 负责流程，SaveService 负责文件。游戏场景隐藏并停用处理后展示结果，避免底层输入穿透。返回主菜单释放游戏场景和信号。
- 视觉复用 GameTheme、已有原创厨房和角色图集，无新增外部资源。1280×720 固定逻辑画布，等比缩放；深绿底、奶油标题、暖金强调、薄荷主操作，胜败兼用文字区分。

验收：首次启动无写档、有效／损坏存档、覆盖确认取消、继续恢复一致、胜败统计、结果不推进模拟、不重复结算、重开清理、返回菜单及鼠标操作与缩放。不得以构造胜败替代八关自然通关验收。

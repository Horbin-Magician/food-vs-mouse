## 参数与操作

- 最多携带 5 种不同美食，至少 1 种且含能攻击的美食；同类选一张实例。初始包子、吐司、布丁各 +0 一张，为不可消耗基础卡，可以强化。其余卡允许锁定，锁定不允许作材料。
- 强化上限 +10；每级生命／直接伤害 +5%，生产量 +2%，在基础值上累加后应用食谱；不增加光环、减速、固定灼烧、放置次数和放置速度。布丁周期仍为 10 秒。新局无星级倍率。
- 每关灵感依次 4、5、6、8、8、10、12、16（简单整局 69；其他难度按 [难度收益](../design/difficulty.md#难度收益2026-09-26) 每关乘系数取整）；失败／放弃保留已通过关卡收益。另有即时保存的击杀灵感拾取；热量跨关保留并承担食谱及刷新消费，金币已取消。具体掉落与防重复规则见 [经济设计](../design/economy.md)。
- 局外 4 个商品，每张 +0 卡 4 灵感，均匀独立抽样允许同名，各槽限购。付费刷新依次 2、4、8、16……，周期结束归零。最多 30 次后拒绝刷新，避免整数溢出。初始灵感 0。
- 每局结算后（胜败或主动结束）免费刷新一次，次数归零；首次创建局外档生成商品。继续、关闭窗口和重复结算不刷新。严格遵循每局刷新，零进度重开也刷新；其无收益刷店风险列入试玩，不擅自增加有效局门槛。
- 主卡当前等级 t，材料等级 m：单卡贡献为 clamp(0.6 × 0.9^max(t-m,0), 0, 1)。1～3 张贡献相加后上限 100%，顺序无关，抽样一次。例：+0 主卡用一张 +0 是 60%，两张 +0 是 100%；+6 主卡用一张 +6 是 60%，+6 和 +5 两张是 100%。不同等级材料共同提高成功率，零材料／超过三张拒绝。无额外灵感手续费、无保底、无重置退款。
- 成功升一级；目标 +1～+6 失败等级不变，+6 升 +7 失败退 +5；其后失败退一级。所有选中的材料成败均消耗。预览显示概率、材料名称等级和失败后等级，提交后清空材料选择，主卡保留选择。
- 进行中对局不可进行局外买卡、刷新、强化和锁卡操作，允许只读查看；要开始新局须明确结束旧局。卡店和强化分为两个页签，卡册支持滚动、选主卡、材料多选、锁卡；单独选卡页开始对局。战报显示本局灵感总额。

## 存档与职责

SaveService 使用 `player.json` v2 单文件，payload 含 revision、meta、run。meta 含既有击杀／食谱、灵感余额、独立卡片实例、选卡、商品及购买状态、刷新次数、局外 RNG、按运行 ID 的奖励／结算流水（含结束统计、种子与各单位伤害等指标）。run 含现有准备快照、携带实例／等级快照及 inspiration_collected（关号字符串→已收最高累计）。旧档缺此字段按空字典；旧 coins 字段忽略，不兑换。卡片实例 ID 是持久字符串 ID，不是 Godot 节点实例 ID。

每次事务重新读取 profile，以 revision 做乐观校验，写临时文件并原子替换。购买、刷新、强化、战斗灵感拾取＋最高累计流水、关后快照＋通关灵感、胜败结算＋刷新＋清除对局均只替换一个文件。存档失败不发布新内存资产，重试从已存 RNG 得到相同结果；重复成功请求使用旧 revision 被拒绝。局外 RNG 不消费战斗 RNG。JSON 中 RNG 使用十进制字符串。

局内交易仍通过 ShopController，持久保存由 RunController／界面协调；失败保持当前页面并阻止开战直到保存成功。关后新状态在开战前重试持久化；奖励流水按运行 ID 的最高通过关避免旧快照刷奖励。结束事务幂等，流水保存已结算状态。

旧版 meta.json、run.json 只读导入，首次成功写 v2 后以 player.json 为权威，不删原文件。旧食谱和击杀保留，初始基础卡补齐，不追溯发灵感；旧局在快照内带 legacy_stars=true，保留原局星级／已买食谱／生命，可继续至结束，但不再买局内卡。旧已通过关卡记为已计账，不补发奖励。新局只读真实收藏。损坏局内快照允许新局替换，但局外数据损坏／未知版本阻止写入，错误可见。

MetaProgression 负责卡片实例、库存／锁卡／材料／选卡规则、概率与交易；SaveService 负责校验和持久化；RunController 管理关卡收益和对局快照；UI 展示与请求。所有经济／概率参数集中在 `resources/progression.tres` 自定义 Resource；`ProgressionDef` 定义导出的属性，运行时读取资源实例。

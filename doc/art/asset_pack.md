生成四张原始 PNG：八美食 4×2 透明图集、八鼠群（含精英和首领）4×2 透明图集、十二食谱 4×3 透明图集、约 16:9 深夜厨房背景。图集等分单元、主体保持留白；通过 Godot AtlasTexture 引用区域，保留生成 alpha，不使用抠色。背景装饰位于边缘，战场采用 [台面透视排布](perspective.md)，细线与半透明格子保留背景纹理，信息面板使用深色底保证阅读。

角色图集 ID 顺序：bun、toast、pudding、tea / pepper、popcorn、noodles、garlic。
鼠群图集 ID 顺序：gray、runner、lid、gnawer / drummer、flour、elite、boss。
食谱图集 ID 顺序：pressure、wide、recycle、burst / ice、cold_spice、burn、long / caramel、breakfast、reheat、crust；未知 ID 返回空纹理，表现层保留文字，不影响业务。

## 图集边缘修整（2026-09-13）

状态：已实现，静态对照与原生渲染验收通过；见 [修整验证](../testing/asset_edges.md)。对应「使用体验」美术缺陷修复。

现有等分区域存在主体跨格：例如小笼包蒸汽、灰鼠尾巴及鼠大厨帽子，会在相邻区域形成残片或平直切面。修整三张透明图集，保持原有 ID 顺序、4×2／4×3 布局和角色辨识特征；每格完整包含主体、附属物和有意保留的蒸汽／粒子，并在四边留透明安全距离。清理孤立杂色及背景残留，保留抗锯齿与合理半透明效果，不全局硬阈值裁剪。

验收：逐格检查完整轮廓与透明留白；Godot 导入无错误；原生窗口复核角色、卡牌及食谱。数值、输入和存档接口不变，无新增运行依赖。最终程序参数和实际验证结果见 [修整验证](../testing/asset_edges.md)。

本轮诊断：原图 alpha > 30 的像素穿过等分界线；foods 在 x=384／768／1152 分别为 99／19／66 个，y=512 为 15 个；mice 在 x=384／1152 为 19／257 个，y=512 为 177 个；recipes 在 y≈683 为 49 个。Codex 内置 image_gen 三次参考图修整均返回 RGB（无 alpha），未接入，源图未修改。用户续办后已按下述程序方案完成修整，未采用生成式修图输出。Godot 4.6.3 下现有 12 组逻辑回归通过，仅作为修改前基线，不表示边缘缺陷已修复。

用户续办后采用程序修整，规则如下：在整张原图上按 alpha > 8 的四邻域连通区域识别主体，避免先按网格截断角色；保留面积至少 20 像素的区域（包括独立爆米花、冰屑、火星），将区域按包围盒中心归入原有单元。向外恢复两像素范围内的原始半透明边缘，不替换主体颜色，不以硬阈值重画轮廓。每张图集统一等比缩小至所有单元均有至少 16 像素透明留白，逐格居中；不放大、拉伸或更改 ID 顺序。透明区 RGB 归零以免缩放采样引入杂色。源文件路径及尺寸保持不变。

处理脚本仅用于离线资产维护，依赖本机 Pillow（实际版本记入验收），不增加游戏运行依赖。脚本以独立输入／输出目录运行，不允许覆盖输入。原图可从修整前的 Git 版本恢复，游戏仅使用修整后的 PNG。验收必须覆盖 alpha 分界线、逐格浅／深底预览，以及原生 Godot 画面；单靠连通区域数量不能证明美术正确。
